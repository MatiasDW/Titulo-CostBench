

OBJETIVOS Objetivo general: Construir un benchmark respaldado por una API que calcule el Costo Total Anual (Annual Total Cost) para cuentas vista según un perfil de uso y recomiende el plan de menor costo esperado para el usuario.
Objetivos específicos:
	•	Consolidar datos oficiales: ingestión y unificación de CMF  y Banco Central (UF) en Parquet.
	•	Estandarizar esquema: definir un esquema canónico y reglas de validación para costos mensuales en CLP y valores normalizados en UF.
	•	Motor de cálculo: implementar un ATC determinista  y generar rankings comparativos.
	•	API y visualización: exponer endpoints mínimos y una vista comparativa básica para la toma de decisiones.
JUSTIFICACIÓN La transparencia financiera permite a consumidores y PYMEs (Pequeñas y medianas empresas) elegir productos bancarios con menor costo total. La CMF publica un simulador con un “costo neto total” mensual por institución y producto, aunque la información está dispersa para comparaciones masivas. Centralizarla, normalizarla con la UF oficial del Banco Central y exponerla mediante un servicio reproducible reduce la asimetría de información y mejora la comparabilidad. En una fase posterior se incorporarán tablas oficiales del SERNAC para ampliar el alcance a tarjetas.
“SERNAC es el organismo público chileno que protege los derechos de los consumidores. En pocas palabras: es la institución que vela porque las empresas cumplan la ley y traten bien a los clientes, recibiendo reclamos, mediando conflictos y fiscalizando prácticas comerciales”

MARCO TEÓRICO: BANK COST BENCHMARK API
Este capítulo profundiza en los fundamentos teóricos y tecnológicos que sustentan el desarrollo de la plataforma. Se abordan desde las arquitecturas de software moderno hasta los modelos matemáticos utilizados para la proyección de indicadores financieros.
Arquitectura de Software y Tecnologías Web
Para el desarrollo de aplicaciones web modernas, escalables y mantenibles, es crucial seleccionar una arquitectura que desacople la lógica de negocio de la interfaz de usuario.
Arquitectura Cliente-Servidor y REST API
El patrón de arquitectura REST (Representational State Transfer) define un conjunto de restricciones para crear servicios web. En este modelo, el Backend (servidor) expone recursos (datos) a través de endpoints HTTP estandarizados (GET, POST, etc.), y el Frontend (cliente) consume estos recursos para renderizar la interfaz. Esto permite que ambos c0ompomentes evolucionen de forma independiente.
Single Page Application (SPA)
Las Single Page Applications (SPA) aplicacion web que carga una sola página HTML y actualiza dinámicamente el contenido a medida que el usuario interactúa con la app, sin recargar la página completa.
	•	React: Biblioteca de JavaScript para construir interfaces de usuario. Utiliza un DOM Virtual para optimizar el renderizado y una arquitectura basada en Componentes reutilizables, lo que facilita el desarrollo modular.
	•	Vite: Herramienta de construcción (build tool), ofrece un entorno de desarrollo extremadamente rápido gracias al uso de módulos ES nativos en el navegador.
Microframeworks con Flask
Flask es un microframework para Python. A diferencia de frameworks "full-stack" como Django, Flask es ligero y no impone una estructura rígida ni dependencias innecesarias. Esto lo hace ideal para construir APIs RESTful eficientes y servicios de microarquitectura, permitiendo integrar fácilmente bibliotecas(como Pandas o Scikit-learn).
Contenerización y Orquestación con Docker
Más allá de la virtualización ligera, Docker se implementa en este proyecto para resolver la complejidad de un entorno políglota (Python y Node.js).
	•	Aislamiento de Dependencias: El backend de Machine Learning requiere librerías de C++ y versiones específicas de Python (para pmdarima y scikit-learn). Docker asegura que estas dependencias no entren en conflicto con el entorno de construcción del frontend.
	•	Docker Compose para Multicontenedor: Se utiliza para orquestar la comunicación entre el contenedor del Backend (Flask), el contenedor del Frontend (Vite/React) y los volúmenes de datos, permitiendo levantar todo el ecosistema con un solo comando.
	•	Escalabilidad Horizontal: La arquitectura contenida permite que la API de benchmark pueda replicarse en múltiples instancias detrás de un balanceador de carga si el volumen de peticiones financieras aumenta.

Machine Learning y Predicción Financiera
El núcleo analítico de la plataforma se basa en la capacidad de predecir comportamientos futuros de indicadores económicos clave.
Series de Tiempo
Una serie de tiempo es una secuencia de puntos de datos indexados en orden cronológico. En finanzas, esto es fundamental para analizar la evolución de activos, acciones o indicadores macroeconómicos.
Modelo ARIMA
El modelo ARIMA (AutoRegressive Integrated Moving Average) es una de las técnicas más robustas para el pronóstico de series temporales.
	•	AR (AutoRegressive): Utiliza la relación entre una observación actual y observaciones previas.
	•	I (Integrated): Aplica diferenciación para hacer la serie estacionaria (eliminar tendencias).
	•	MA (Moving Average): Utiliza la dependencia entre una observación y el error residual de modelos previos.
Se utiliza la librería pmdarima para la selección automática de los hiperparámetros óptimos $(p,d,q)$ del modelo mediante el algoritmo auto_arima, optimizando el criterio de información de Akaike (AIC).
$p$ (Orden Autoregresivo - AR)
Representa el número de lags (observaciones pasadas) que el modelo utiliza para predecir el valor actual.
	•	Si p=2, el modelo asume que el valor de hoy depende directamente de lo que pasó ayer y anteayer. Se basa en la correlación entre los datos actuales y sus valores anteriores.
$d$ (Grado de Diferenciación - I)
Indica el número de veces que se deben restar las observaciones pasadas a las actuales para que la serie de tiempo sea estacionaria.
	•	Una serie es estacionaria cuando sus propiedades estadísticas (media y varianza) son constantes en el tiempo. Si tus datos financieros tienen una tendencia alcista clara, el parámetro d se encarga de "eliminar" esa tendencia para que el modelo pueda trabajar con la variación real de los datos.
$q$ (Orden de Media Móvil - MA)
Representa el tamaño de la ventana de errores de pronóstico anteriores que se incorporan al modelo.
	•	En lugar de mirar los valores pasados directamente (como hace p), q mira qué tan "equivocado" estuvo el modelo en los días anteriores. Ayuda a suavizar choques aleatorios o ruido en los datos financieros.
Métricas de Evaluación
	•	MAPE (Mean Absolute Percentage Error): Mide el tamaño del error en términos porcentuales. Un MAPE bajo (ej. < 5%) indica un modelo altamente preciso y confiable para proyecciones de UF e IPC.

Contexto Económico y Financiero
La aplicación opera sobre un dominio específico: el mercado financiero chileno y sus indicadores regulatorios.
Indicadores Macroeconómicos
	•	UF (Unidad de Fomento): Unidad reajustable según la inflación chilena. Su predicción es crítica para la planificación de créditos hipotecarios y de consumo.
	•	IPC (Índice de Precios al Consumidor): Medida principal de la inflación interna que determina el valor diario de la UF.
	•	Bonos del Tesoro (Treasury Yields): Las tasas de los bonos de EE.UU. (10 años) actúan como tasa libre de riesgo global, influyendo en las tasas de interés locales.
Costo Total Anual (CTA)
El CTA es un indicador obligatorio en Chile que resume todos los costos asociados a un producto financiero (tasas, comisiones, seguros) en un solo porcentaje anual, facilitando la transparencia y comparación.
Inteligencia Artificial Generativa y LLMs
Large Language Models (LLMs)
Modelos de aprendizaje profundo (ej. Gemini) capaces de entender instrucciones complejas y generar texto coherente basado en vastos conjuntos de datos.
Generación Aumentada por Recuperación (RAG)
Para que el LLM entregue insights reales sobre el mercado chileno, se utiliza la técnica RAG (Retrieval-Augmented Generation).
	•	Se "inyecta" información fresca (el valor de la UF del día o el ranking actual de costos de la API) en el contexto del prompt.
	•	Evitar "alucinaciones" del modelo y asegurar que los consejos financieros estén basados en los datos calculados por la plataforma en tiempo real.
